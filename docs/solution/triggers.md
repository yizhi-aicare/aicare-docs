# 情景与触发规则

一套话术打天下会顾此失彼：售前要热情推销，售后要安抚解决。「情景配置」允许你在一个方案里为不同客户情景配置专用的回复设定和触发规则。

入口：方案编辑器 → 「AI 设置」→ 右上角「情景配置」。

::: warning 按套餐开放
自定义触发规则和多情景分流属于部分套餐的权益（客户端里标注「创始版权益」）。当前套餐未包含时请联系销售开通，见[套餐与开通](/start/plan)。
:::

## 默认设置和情景

- 每个方案有且仅有一个**默认设置**：没有命中任何触发规则的消息由它处理。默认设置不能配置触发规则。
- **情景**是额外的回复设定：售后情景、议价情景、大促咨询情景……每个情景有自己的角色设定和话术要求。
- 情景可以单独**停用**：停用后即使触发规则命中也会跳过，回到默认设置处理。

## 触发规则

触发规则决定什么时候切换到某个情景。每个情景可以加多条触发条件，支持两种：

- **关键词**：消息里出现指定词时命中。比如「退款、退货、坏了」触发售后情景。
- **意图描述**：用一句话描述这类客户想干什么，AI 语义判断是否命中。比如「顾客对价格不满意，想要优惠」。

关键词准确但死板，意图描述灵活但依赖 AI 判断。拿不准就两种都配。

## 配置步骤

1. 在情景配置页新建情景，写好名字和这个情景专用的回复设定。
2. 打开该情景的「触发规则」标签页，添加触发条件。
3. 启用情景。
4. 用[对话测试](/solution/test)验证：发几条应该命中的消息，确认路由说明里显示进入了正确的情景。

## 使用建议

- **从少开始**。先只拆一个售后情景，跑顺了再细分。情景太多、触发规则互相重叠，反而难排查。
- **触发规则要互斥**。两个情景都配了「退款」这个词，命中哪个不直观。规则尽量不重叠。
- **在聊天记录里核对**。[会话详情](/workspace/records#会话详情)的路由说明会写明这条消息由哪个情景处理、怎么命中的，是排查分流问题的第一手资料。
